# B.3R V2-1 GPU operator handoff

The user prioritized GPU progress on 2026-10-05 UTC while the V2-0C validation plan remained deferred. This batch adds an isolated frozen-graph `J W Jᵀ` product in `CoupledContactOperator.compute` and a diagnostic C# caller. It does not replace the current legacy GPU solver, mutate existing proof/gameplay buffers, or select the V2 path in the player.

The caller accepts bounded 8,210-endpoint / 262,144-row arrays of body center and inverse mass/inertia, normalized contact direction, common point and inverse square root of the true diagonal. It validates row scaling against physical mass/inertia. For each row, the GPU expands equal/opposite linear and angular reactions. CPU-built incidence is split into at most 64 row sides per segment. One GPU workgroup reduces each segment; a separate body pass sums segment reactions and applies inverse mass/inertia once. A final row pass gathers the resulting relative velocity and applies the same row scaling. Dispatch stage count is independent of incident degree; a 4,096-point hull needs 64 segment groups for its endpoint. This avoids per-contact floating-point atomics and degree division of physical mass.

Focused Editor cases are defined for an off-center two-body contact with explicit linear/spin expectations and 200/4,096-point finite-hull reactions. They were **not run** under the user's no-tests direction. No Unity import, Metal compile, GPU dispatch, readback, layout, product or performance claim is available. The caller currently uses synchronous diagnostic readback and CPU-supplied frozen rows. GPU manifold generation, GPU-owned incidence/CSR, the full operator on archived graphs, explicit production arena, masked C1–C3 schedules, cost measurement, V2-2 Newton step, V2-3 qualification and V2-4 gameplay integration remain open. V2-0C's nine packed references are also unverified; no physical acceptance claim follows from this source change.

## Convex pair to GPU operator continuation

An opt-in constructor now accepts up to 65,536 convex candidate pairs and body records. In one command sequence the manifold shader emits up to two clipped points, expands each into scaled normal and tangent rows using the true endpoint mass/inertia, and writes four fixed row slots per pair. Inactive slots have zero inverse root and are skipped by GPU incidence and operator kernels. This connects pair geometry to GPU `J W Jᵀ` without a CPU manifold/row readback between stages. The existing CPU-row constructor remains for explicit frozen-product comparisons. Diagnostic result readback includes active rows, endpoint motion and row velocity; it is still synchronous. Fixed slots, supplied candidate pairs, convex-only geometry and synchronous readback are diagnostic limits, not the final compact arena or gameplay contract. There is still no compile, physical acceptance or timing result.
