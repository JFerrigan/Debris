# B.3R V2-1 GPU operator handoff

The user prioritized GPU progress on 2026-10-05 UTC while the V2-0C validation plan remained deferred. This batch adds an isolated frozen-graph `J W Jᵀ` product in `CoupledContactOperator.compute` and a diagnostic C# caller. It does not replace the current legacy GPU solver, mutate existing proof/gameplay buffers, or select the V2 path in the player.

The caller accepts bounded 8,210-endpoint / 262,144-row arrays of body center and inverse mass/inertia, normalized contact direction, common point and inverse square root of the true diagonal. It validates row scaling against physical mass/inertia. For each row, the GPU expands equal/opposite linear and angular reactions. CPU-built incidence is split into at most 64 row sides per segment. One GPU workgroup reduces each segment; a separate body pass sums segment reactions and applies inverse mass/inertia once. A final row pass gathers the resulting relative velocity and applies the same row scaling. Dispatch stage count is independent of incident degree; a 4,096-point hull needs 64 segment groups for its endpoint. This avoids per-contact floating-point atomics and degree division of physical mass.

Focused Editor cases are defined for an off-center two-body contact with explicit linear/spin expectations and 200/4,096-point finite-hull reactions. They were **not run** under the user's no-tests direction. No Unity import, Metal compile, GPU dispatch, readback, layout, product or performance claim is available. The caller currently uses synchronous diagnostic readback and CPU-supplied frozen rows. ## Convex manifold source continuation

`CoupledManifoldProbe.compute` adds a separate GPU narrow-phase probe for two oriented rectangles supplied as candidate pairs. It evaluates all eight directed SAT faces, selects one stable maximum-separation reference face, clips the opposing incident edge, and emits the distinct one or two contact points with signed gaps and an A→B normal. A diagonal corner tie emits one clipped point rather than two perpendicular constraints. The probe is separate from the legacy `ParallelContactGeometry.hlsl`, whose representative midpoint/tied-axis behavior is not the V2 manifold contract. A focused Editor case defines the flat two-point and diagonal one-point expectations; it was **not run**. This source step does not yet handle occupied unions, exterior-face ownership, rigid boundary pairs, broad phase, GPU compacted row storage or connection to the operator. It does not change the V2-1 gate status.

## GPU incidence continuation

The frozen operator now builds its endpoint incidence from supplied rows on the GPU. It clears body degrees/cursors, atomically counts both sides of each row, performs a two-level exclusive scan for adjacency and 64-entry segment starts, scatters row-side indices, and builds segment descriptors. A GPU-written indirect dispatch runs exactly the populated reduction groups. The CPU still validates row scaling and computes an expected segment count for diagnostic comparison; it no longer uploads adjacency or segment lists. Buffer capacity is bounded by 8,210 endpoints and 262,144 rows. Empty and repeated-product cases are defined for a later Editor pass. This change has **not** been imported, compiled, run or timed under the user's no-tests direction. It does not yet connect the convex manifold probe to GPU row creation or establish a production asynchronous completion path.
